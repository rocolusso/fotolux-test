# fotolux-verify

Одностраничная заглушка на двух языках для верификации карточки Google Business Profile.

Не финальный сайт. Задача одна: дать домену `fotolux.md` живое содержимое, которое
верификатор Google сможет сверить с карточкой. Полноценный сайт строится отдельно
по `SEO-MODEL.md` и `FRONTEND.md`.

## Что внутри

|                                           |                                                                                      |
| ----------------------------------------- | ------------------------------------------------------------------------------------ |
| Next.js 15, App Router, TypeScript, `src` |                                                                                      |
| Tailwind 4                                | токены из `FRONTEND.md`, тёплые нейтрали, светлая тема                               |
| Локали                                    | `ru` на корне `/`, `ro` в `/ro` — полное зеркало                                     |
| Server Components                         | клиентских компонентов нет ни одного                                                 |
| SEO                                       | canonical, hreflang `ru-MD` / `ro-MD` / `x-default`, OG, `sitemap.xml`, `robots.txt` |
| JSON-LD                                   | `ProfessionalService` без `address` — это service-area business — плюс `WebSite`     |
| Изображения                               | `next/image`, AVIF и WebP, hero с `priority`, остальное лениво                       |

## Перед публикацией — обязательно

Все поля в `src/shared/config/site.ts` должны совпадать с карточкой GBP **до символа**.
Расхождение сайта и карточки — типовая причина отказа в верификации.

- [ ] `name` — `Fotolux`, ровно как в карточке. Латиницей в обеих локалях, не добавлять услуги и города
- [ ] `phone` и `phoneDisplay` — заменить на настоящий
- [ ] `email` — почта на домене, не gmail
- [ ] `areas` — совпадают с зонами обслуживания в карточке
- [ ] `NEXT_PUBLIC_SITE_URL` — тот же адрес, что указан в карточке
- [ ] Картинки в `public/images/` заменить на свои

## Изображения

> ⚠️ **`public/images/` не перегенерировать.** Файлы там заменены настоящими
> снимками. Любой скрипт, который «обновляет плейсхолдеры», затирает работу
> без возможности отката — мост к диску пишет поверх, минуя корзину.
> Менять содержимое папки может только владелец, вручную.

Изначально это были сгенерированные заглушки. Замена — свои файлы с теми же
именами, размеры сохранить.

| Файл            | Размер    | Где                |
| --------------- | --------- | ------------------ |
| `hero.jpg`      | 2000×1250 | первый экран       |
| `work-1..6.jpg` | 1200×1500 | галерея, 4:5       |
| `about.jpg`     | 1400×1050 | блок о студии, 4:3 |
| `og.jpg`        | 1200×630  | превью в соцсетях  |

## Запуск

```bash
cp .env.example .env      # заполнить NEXT_PUBLIC_SITE_URL
yarn install
yarn dev                  # http://localhost:3000
yarn build && yarn start
```

Пакетный менеджер — **yarn**, один на проект. `yarn.lock` — источник истины,
его же использует Dockerfile через `--frozen-lockfile`. Если в папке появится
`package-lock.json`, удалить: два лок-файла расходятся в версиях, и то, что
собралось локально, перестаёт совпадать с тем, что собралось в контейнере.

## Деплой на VPS

```bash
docker buildx build --platform linux/amd64,linux/arm64 -t fotolux-verify .
docker compose up -d
```

Порты наружу не пробрасываются: трафик заходит через Cloudflare Tunnel.
В панели Cloudflare публичный хостнейм направить на `app:3000`.

## Две вещи, о которых стоит знать

**Postgres в compose нет.** Стандарт предполагает `app` + `postgres`, но здесь нет
ни одного динамического данных — всё статично. Добавлять базу ради соответствия
схеме смысла нет; в полном проекте она появится вместе со Strapi.

**Шрифты тянутся с Google Fonts при сборке.** `next/font/google` скачивает их
на этапе билда, поэтому машине сборки нужен интернет. В рантайме внешних запросов
уже нет — шрифты отдаются с твоего домена.

**Проверь румынские `ș` и `ț`.** Forum и Manrope подключены с подмножеством
`latin-ext`, буквы должны быть с запятой снизу, а не с седилью. Проверочная строка
на `/ro`: `Ședințe foto în Chișinău și Bălți`.
